# 복약 트래커

복용 간격과 하루 최대치를 기준으로 **다음 복용 가능 시각**을 계산해 주는 PWA.
기록의 **원본은 기기의 `localStorage`**이고, 클라우드 백업은 직접 켜야 동작하는 사본입니다.

배포 주소: https://leedalnim.github.io/med-tracker/

## 기능

### 복약 기록
- 약마다 기록 방식 선택: **간격 트래커**(다음 복용 가능 계산) 또는 **복용 체크**(하루 1회, 먹었는지만 기록)
- 간격 트래커형: 최소 복용 간격(시간)·1일 최대 개수 등록, 다음 복용 가능까지 **남은 시간을 원형 카운트다운 링**으로 실시간 표시
- 다음 복용 가능 시각은 `마지막 복용 + 최소 간격`으로 계산합니다. 1일 최대치는 이 계산에 쓰이지 않고, 오늘 기록이 최대치에 닿으면 '오늘 최대' 상태로 따로 표시합니다 (초과 시 경고 배너)
- 예정 시각 **3분 전**부터는 미리 눌러 기록할 수 있습니다
- **카드를 누르면 약 상세**: 대형 히어로 링(실시간 카운트다운), 오늘 복용량·1일 최대·최소 간격 요약, 복용 내역(시각 수정·삭제), **지난 날짜 기록 직접 추가**, 약 정보 수정
- **약 관리 레이어 팝업**: 홈 표시 / 즐겨찾기 / 약별 알림을 한곳에서. 홈에서 내려도 복용 기록은 그대로 남고, 다시 올리면 이어집니다

### 달력
- 날짜별 복용 기록 확인·시간 수정·삭제
- **생리주기 트래킹** (기본 꺼짐, 설정에서 켬): 생리·부정출혈 기록, 다음 생리 예정일·배란 예정일·가임기 예측
- 기록이 2회 이상이면 **실제 간격의 평균**(최근 6주기)으로, 1회뿐이면 **설정해 둔 평균 주기**(기본 28일)로 계산합니다. 설정값으로 계산했을 땐 화면에 그렇게 표시됩니다
- 예측은 보고 있는 달에 맞춰 계산하므로 몇 년을 넘겨도 끊기지 않습니다

### 복약 알림
폰은 스스로 깨어나지 못하므로, **'다음 복용 시각'을 서버에 맡기고 그 시각에 서버가 푸시를 보내는** 구조입니다.

```
앱: 약·기록·알림설정 변경 → 예약 목록을 서버에 동기화
서버: pg_cron 매분 → Edge Function → 때가 된 예약만 발송
```

- 약마다 **간격 기준**(마지막 복용 + 간격) 또는 **매일 정해진 시각** 중 선택
- 알림을 누르면 해당 약 화면으로 바로 이동
- iOS에서는 **홈 화면에 추가한 PWA에서만** 동작합니다 (iOS 16.4+). 일반 알람이 아니라 푸시 알림이라 무음 모드의 영향을 받습니다
- 자기 저장소에 배포해 알림까지 쓰려면 Supabase 설정이 필요합니다 → [`PUSH_SETUP.md`](PUSH_SETUP.md)

### 백업
- **파일 내보내기 / 불러오기**: 전체 데이터를 JSON 한 덩어리로 저장·복원
- **클라우드 백업(Supabase)**: 기본 꺼짐. 켜면 저장할 때마다 뒤에서 조용히 올라가고, 실패해도 로컬 기록은 그대로입니다
  - 새 기기는 항상 꺼짐으로 시작합니다 — 빈 데이터가 클라우드를 덮어쓰는 사고를 막기 위해서입니다
  - 복원은 사용자가 직접 누를 때만 일어납니다
  - 복구 코드(UUID)를 아는 기기만 접근할 수 있습니다. 테이블은 RLS를 켜고 정책을 두지 않은 뒤, `SECURITY DEFINER` 함수로만 접근합니다

### 기본 등록 약 / 자주 쓰는 약 선택
설치하면 아래 약들이 미리 등록돼 있고(수정·삭제 가능), 약 추가 폼에서도 선택하면 간격·최대치·단위까지 자동 입력됩니다. 진통제 용법은 식약처 허가 용법 기준:
- 타이레놀정 500mg — 최소 간격 4시간, 1일 최대 8정
- 타이레놀 8시간 이알 서방정 650mg — 최소 간격 8시간, 1일 최대 6정
- 이지엔6프로 (덱시부프로펜 300mg) — 최소 간격 4시간, 1일 최대 4캡슐
- 부루펜정 400mg (이부프로펜) — 최소 간격 4시간, 1일 최대 3정
- 탁센 (나프록센 250mg) — 최소 간격 6시간, 1일 최대 5캡슐
- 로수바이브정 · 본비바정 150mg(월 1회) · 라바로브정 · 라바로하이정 — 복용 체크형

## 설치 (홈 화면에 추가)
- **iPhone (Safari)**: 주소 열기 → 공유 버튼 → "홈 화면에 추가"
- **Android (Chrome)**: 메뉴(⋮) → "앱 설치" 또는 "홈 화면에 추가"
- 설치하면 주소창 없는 전체화면 앱으로 실행되고 오프라인에서도 동작합니다.

## 기술 구성
- **Vanilla JS 단일 페이지(SPA), 프레임워크·빌드 도구 없음.** `package.json`도 없습니다
- 저장은 `localStorage`가 원본 (쓸 수 없는 환경에서는 메모리로 폴백). 날짜가 바뀌면 "오늘 복용량"만 자동 리셋되고 이력은 보존
- PWA: `manifest.json` + 서비스워커(`sw.js`) — 홈 화면 설치, 오프라인 동작, 푸시 수신
- 알림 서버: Supabase (Postgres + Edge Functions + `pg_cron`), Web Push(VAPID)
- 모바일 우선 반응형, 다크모드(`prefers-color-scheme` 및 수동 선택) 대응
- 상대 경로만 사용 → GitHub Pages 프로젝트 경로(`/med-tracker/`)에서 그대로 동작

```
index.html     화면 뼈대
app.js         전부 — 상태, 계산, 렌더, 이벤트 (IIFE)
style.css      디자인 토큰 + 모든 스타일
sw.js          서비스워커 (오프라인 캐시 + 푸시 수신)
manifest.json  PWA 설정
supabase/      서버 쪽 (SQL, Edge Function)
```

## GitHub Pages 배포
- **Settings → Pages → Source: Deploy from a branch (`main`, `/root`)** 로 설정되어 있음
- 빌드 단계가 없으므로 Actions 워크플로를 두지 않습니다. `main`에 푸시하면 GitHub이 자동으로 재배포합니다
- 앱을 고칠 때는 `app.js`의 `APP_VERSION`과 `sw.js`의 `CACHE_NAME`을 **둘 다** 올려야 합니다. 하나만 올리면 설치된 PWA가 옛 버전을 계속 씁니다
- 설정 맨 아래 `버전 · 업데이트 확인`으로 강제로 확인할 수 있습니다

## 참고
- 이 앱은 의학적 판단을 하지 않습니다. 사용자가 등록한 간격·최대치·날짜를 기준으로 계산만 합니다
- 생리주기의 배란·가임기는 통계적 추정치입니다. 피임·임신 계획의 근거로 삼지 마세요
- 저장소가 공개이므로 VAPID **공개키만** 코드에 있고, 비밀키와 크론 시크릿은 Supabase Secrets에만 둡니다
